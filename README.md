# Анализ тарифных планов

Разбор счетов оператора связи для корпоративных номеров: система читает
выгрузку, считает фактическое потребление каждого номера и показывает,
**за что платит компания, а за что сотрудник** и **кто занимает пакет,
которым не пользуется**.

Работает на чистом Python из стандартной библиотеки. Внешних зависимостей
нет ни одной — ни `pip install`, ни интернета при установке не требуется.

---

## Установка в закрытом контуре

1. Скачать архив репозитория (`Code` → `Download ZIP`) и распаковать.
2. В папке с файлами выполнить:

```
python install.py
```

3. Запустить:

```
python server.py 3001
```

4. Открыть <http://localhost:3001>

Всё. База создастся сама при установке, справочники заполнятся, интернет
не понадобится ни на одном шаге.

**Требуется:** Python 3.9 или новее. Проверить: `python --version`.

### Что делает установщик

| Шаг | Что происходит |
|---|---|
| 1 | Проверяет версию Python |
| 2 | Проверяет, что все файлы приложения на месте |
| 3 | Создаёт базу и разворачивает **18 таблиц** |
| 4 | Заполняет справочники: 7 цветов-правил, 6 пометок, 28 правил оплаты, 4 статуса |
| 5 | Прогоняет самопроверку — база читается, расчёт запускается |

Повторный запуск безопасен: таблицы создаются через `IF NOT EXISTS`,
справочники досеиваются только недостающие, данные не трогаются.

## Структура базы

Схема — в файлах `schema.sql` (SQLite) и `schema_postgres.sql` (PostgreSQL).

Оба **сгенерированы** из `db.py` и руками не правятся. Единственный источник
схемы — код, иначе живая база и приложение неизбежно разъедутся. Пересобрать
файлы после правки схемы:

```
python install.py --dump-schema
```

Файлы нужны, чтобы посмотреть структуру не читая код, и чтобы развернуть
базу руками там, где python запускать нельзя. Само приложение их не читает.

### Основные таблицы

| Таблица | Что хранит |
|---|---|
| `users_numbers` | абоненты: номер, ФИО, должность, лимит |
| `reports` | счёт номера за месяц |
| `pvalues` | строки услуг внутри счёта |
| `pname` | каталог названий услуг |
| `invoice_meta` | реквизиты и итоги счёта |
| `tariff_plans` | каталог тарифов для подбора |
| `chip_rules` | **правила номера**: цвета и пометки в одной таблице, различает поле `kind` |
| `chip_rule_links` | какие правила навешены на какой номер |
| `chip_settings` | заметка и ручное переопределение плательщика |
| `payment_rules` | правила «кто платит» по названию услуги |
| `business_trips` | командировки: период, страна, утверждение |
| `app_statuses` | статусы сотрудников |
| `app_settings` | настройки приложения |

Таблицы `chip_colors`, `chip_marks`, `chip_mark_links` — **устаревшие**.
Данные из них перенесены в `chip_rules` миграцией; сами таблицы оставлены
как путь отката и в работе не участвуют.

## Где лежит база

По умолчанию — файл `megafon.db` рядом с приложением. Другой путь задаётся
переменной окружения:

```
set MEGAFON_DB=D:\data\megafon.db          Windows
export MEGAFON_DB=/var/lib/megafon.db      Linux
```

База в репозиторий **не попадает никогда** — она в `.gitignore` вместе со
всеми копиями и бэкапами. В ней абонентские номера.

## Как пользоваться

**Меню → Загрузить счёт** — выгрузка оператора «Начисления по абонентским
номерам». Формат: `.txt` или `.csv`, разделитель `;`.

**Меню → Список абонентов** — ФИО, должности, лимиты. Без него номера
показываются просто цифрами.

**Меню → Командировки** — период, страна, утверждение. Командировка,
пересекающаяся с месяцем счёта, переводит роуминг номера на компанию.

Для проверки, что всё работает, в архиве лежит образец `otche.csv`
(13 номеров, синтетические данные).

## Разделение оплаты

По умолчанию:

| Корзина | Кто платит |
|---|---|
| Абонентская плата | компания |
| Опции и сервисы | компания |
| Перерасход пакета | сотрудник |
| Роуминг | сотрудник |

Умолчания переопределяются, и порядок разбора такой:

1. ручная настройка номера (шестерёнка в карточке);
2. **правило-цвет** — у номера одно, красит карточку;
3. **правила-пометки** — их может быть несколько;
4. командировка — только для роуминга;
5. правило по названию услуги;
6. умолчание из таблицы выше.

Всё это правится в интерфейсе, без правки кода: **Меню → Настройки →
Правила чипсов** и **Правила оплаты**.

## Дополнительные инструменты

### Конвертер выгрузок

```
python convert.py otche.txt
```

Делает четыре файла: три для Excel (абоненты, услуги, итоги) и один
`.bill.csv` — его можно загрузить обратно в приложение. После конвертации
выполняется круговая сверка: файл разбирается тем же парсером, что и на
сайте, и суммы сравниваются с исходником.

### Витрина на PostgreSQL

```
python deploy.py                             посмотреть, что будет сделано
python deploy.py --run --with-data           развернуть и перенести данные
python deploy.py --run --with-data --fresh   то же, очистив цель
```

Разворачивает ту же схему на PostgreSQL и переносит данные. Работает через
`psql`, который идёт вместе с сервером PostgreSQL — скачивать ничего не надо.

**Приложение при этом остаётся на SQLite.** Переезд целиком потребовал бы
пакета `psycopg`, то есть внешней зависимости, а в закрытом контуре мы их
не тащим. PostgreSQL используется как витрина для отчётности.

## Устройство кода

| Файл | Отвечает за |
|---|---|
| `server.py` | HTTP, API, разбор загружаемых файлов |
| `db.py` | подключение к базе, схема, миграции |
| `queries.py` | все обращения к базе |
| `domain.py` | подбор тарифа, рекомендации |
| `billing.py` | разделение оплаты, индекс невыгодности |
| `seeds.py` | стартовые справочники |
| `index.html` `script.js` `style.css` | интерфейс, без сборки и фреймворков |
| `install.py` | установка |
| `convert.py` | конвертер выгрузок |
| `deploy.py` | развёртывание на PostgreSQL |
