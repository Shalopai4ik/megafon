# Анализ тарифных планов

Разбор счетов оператора связи для корпоративных номеров: система читает
выгрузку, считает фактическое потребление каждого номера и показывает,
**за что платит компания, а за что сотрудник** и **кто занимает пакет,
которым не пользуется**.

Данные лежат в **PostgreSQL**. Приложение работает на чистом Python из
стандартной библиотеки: `pip install` не нужен, интернет при установке не
нужен, драйвера базы в системе нет и не требуется — с PostgreSQL приложение
разговаривает через `psql`, который ставится вместе с самим сервером.

---

## Установка в закрытом контуре

**Требуется:** Python 3.9 или новее и установленный PostgreSQL (нужен его
`psql`). Проверить: `python --version`, `psql --version`.

1. Скачать архив репозитория (`Code` → `Download ZIP`) и распаковать.
2. Прописать, куда подключаться, — файлом `pg.conf` рядом с приложением:

```
host     = 127.0.0.1
port     = 5432
database = megafon
user     = megafon
password = megafon
```

Файла может не быть вообще: тогда берутся эти же значения по умолчанию.
Переменные окружения `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`,
`PGPASSWORD` перекрывают файл.

3. В папке с файлами выполнить:

```
python install.py
```

4. Запустить:

```
python server.py 3001
```

5. Открыть <http://localhost:3001>

Базу и пользователя установщик создаёт сам, если их ещё нет, — для этого ему
нужен доступ суперпользователя: `PGSUPERUSER` (по умолчанию `postgres`) и
`PGSUPERPASS`. Если базу заводит администратор, эти переменные не нужны:

```sql
CREATE ROLE megafon LOGIN PASSWORD 'megafon';
CREATE DATABASE megafon OWNER megafon;
```

### Что делает установщик

| Шаг | Что происходит |
|---|---|
| 1 | Проверяет версию Python |
| 2 | Проверяет, что все файлы приложения на месте |
| 3 | Находит `psql` и проверяет связь с сервером |
| 4 | Создаёт базу и пользователя, если их нет |
| 5 | Разворачивает таблицы и индексы, достраивает новые колонки |
| 6 | Показывает справочники, которые лягут в базу при первой загрузке |
| 7 | Прогоняет самопроверку — база читается, расчёт запускается |

Повторный запуск безопасен: таблицы создаются через `IF NOT EXISTS`, колонки
через `ADD COLUMN IF NOT EXISTS`, данные не трогаются.

### После установки база ПУСТАЯ

В ней есть таблицы и больше ничего — ноль строк. Ни счетов, ни абонентов, ни
справочников. Первая строка появляется в базе тогда, когда через сайт
загрузили файл, и ни секундой раньше.

Так сделано намеренно. Раньше справочники заливались на старте приложения:
сервер поднимался — и в базе сразу лежало полторы сотни строк, которых туда
никто не загружал. Посмотреть в базу и понять, что в ней реальные данные, а
что приложение досочинило само, было нельзя. Теперь ответ однозначный: всё,
что лежит в базе, туда загрузили.

Справочники — правила номеров, правила оплаты, зоны роуминга,
каталог тарифов — материализуются **в момент первой загрузки**, вместе с
первым счётом. До этого экраны настроек показывают те же значения
**из памяти**: пустым интерфейс не выглядит, а база остаётся нетронутой.
Проверить, что уже легло, можно на `/raw` и в «Меню → Что загружено».

### Перенос данных со старой версии

Если приложение уже работало на SQLite, рядом лежит файл `megafon.db`.
Разовый скрипт переливает его содержимое в PostgreSQL:

```
python import_sqlite.py                  посмотреть, что будет
python import_sqlite.py --run            перенести
python import_sqlite.py --run --fresh    очистить цель и перенести
```

В конце печатается сверка по строкам — смотреть на неё обязательно.

Перенос вставляет строки **вместе с их прежними id** — иначе развалятся
ссылки между таблицами. Счётчики `BIGSERIAL` при такой вставке не двигаются,
поэтому после переноса они принудительно догоняются до фактических максимумов
(`db.sync_sequences`). Без этого шага перенос выглядит успешным, приложение
читает и считает — а разваливается позже, на первой же загрузке счёта:
«ключ (id)=(1) уже существует». То же лечение прогоняется при обновлении
схемы, так что базы, перенесённые старой версией, чинятся сами.

## Структура базы

Схема — в файле `schema.sql`. Он **сгенерирован** из `db.py` и руками не
правится. Единственный источник схемы — код, иначе живая база и приложение
неизбежно разъедутся. Пересобрать файл после правки схемы:

```
python install.py --dump-schema
```

Файл нужен, чтобы посмотреть структуру не читая код, и чтобы развернуть базу
руками там, где python запускать нельзя (`psql -d megafon -f schema.sql`).
Само приложение его не читает.

### Основные таблицы

| Таблица | Что хранит |
|---|---|
| `users_numbers` | абоненты: номер, ФИО, должность, лимит |
| `reports` | счёт номера за месяц |
| `pvalues` | строки услуг внутри счёта |
| `pname` | каталог названий услуг |
| `invoice_meta` | реквизиты и итоги счёта |
| `tariff_plans` | каталог тарифов для подбора |
| `chip_rules` | **правила номера**: цвета и пометки в одной таблице, различает поле `kind`; `match_limits` — лимиты-признаки, `is_self_paid` — «платит сам» |
| `chip_rule_links` | какие правила навешены на какой номер |
| `chip_settings` | заметка и ручное переопределение плательщика |
| `payment_rules` | правила «кто платит» по названию услуги |
| `business_trips` | командировки: период, страна, утверждение |
| `roaming_zones` | ставки роуминга по зонам — справочник для сверки |
| `app_settings` | настройки приложения |

Таблицы `chip_colors`, `chip_marks`, `chip_mark_links` и `app_statuses` —
**устаревшие**. Данные из них перенесены в `chip_rules` миграцией; сами
таблицы оставлены как путь отката и в работе не участвуют. Колонка
`users_numbers.status` там же: приложение её больше не читает.

## Как приложение разговаривает с базой

Драйвера PostgreSQL в стандартной библиотеке Python нет, а любой внешний
(`psycopg`, `psycopg2`) — это колесо под конкретную связку «версия питона +
архитектура + glibc», которое в закрытый контур надо сначала протащить, а
потом сопровождать при каждом обновлении системы.

Поэтому обмен идёт через `psql`: он уже стоит вместе с сервером и обновляется
вместе с ним. Запрос уходит ему в stdin, ответ забирается из stdout в виде
JSON (`row_to_json`) — так значения не портятся ни кавычками, ни переводами
строк, ни русским текстом.

Практические следствия, которые видно в коде:

* запись пачками идёт **одной транзакцией** (`db.transaction`) — и ради
  целостности, и потому что каждый выход в базу это отдельный запуск `psql`;
* внутри такого блока у команды нет результата: читать нужно до или после;
* всё, что нужно расчёту месяца, читается несколькими запросами на весь парк
  сразу (`queries.month_dataset`), а не по запросу на абонента.

Настройки подключения — `pg.conf` рядом с приложением, поверх него
переменные `PG*`. Файл в репозиторий **не попадает**: в нём пароль.
`psql` ищется в `PATH`, затем в стандартных каталогах установки; путь можно
задать явно переменной `MEGAFON_PSQL`.

## Как пользоваться

**Меню → Загрузить счёт** — выгрузка оператора «Начисления по абонентским
номерам». Формат: `.txt` или `.csv`, разделитель `;`. Кодировка любая из
UTF-8 (в том числе с BOM) и Windows-1251 — определяется сама.

Разбор опирается на структуру, а не на номера колонок, поэтому один и тот же
файл читается и как `.txt`, и как `.csv`. Блок каждого номера выглядит так:

```
Абонентский номер 9001234567
Тарифный план на 31.01.2026 «Федеральный Специальный B2B»
Название услуги;Объём;Сумма без скидки;Сумма скидки;Сумма со скидкой
Абонентская плата по тарифному плану;31 шт;400.00;0.00;400.00
Абонентская плата за услугу Защита сотрудников;90.00;0.00;90.00
Мобильный интернет в домашнем регионе;15.61 Мбайт;0.72;0.00;0.72
Итого начислено;111.36;0.00;111.36
в том числе НДС (22%);20.08
```

Обратите внимание на вторую строку услуги: колонки «Объём» у неё нет, полей
четыре вместо пяти. Так в счёте и приходит, разбор это учитывает. Переживает
он и то, что выгрузку переслали в мессенджере (штампы `[дата] Имя:`),
и разрывы строки посреди записи, и пустые колонки Excel между значениями.

**Повторная загрузка того же месяца перезаписывает его целиком** — задвоить
расходы, загрузив файл дважды, нельзя. Разные месяцы накапливаются: так
набирается история.

**Меню → Список абонентов** — ФИО, должности, лимиты. Без него номера
показываются просто цифрами.

**Меню → Командировки** — период, страна, утверждение. Командировка,
пересекающаяся с месяцем счёта, переводит роуминг номера на компанию.

> Образцов выгрузок в архиве нет намеренно: в них абонентские данные.
> В репозитории лежит только то, что нужно для развёртывания.

## Разделение оплаты

По умолчанию:

| Корзина | Кто платит |
|---|---|
| Абонентская плата | компания |
| Опции и сервисы | компания |
| Перерасход пакета | сотрудник |
| Роуминг | сотрудник |

Умолчания переопределяются, и порядок разбора такой:

1. ручная настройка номера (шестерёнка в карточке);
2. **правило-цвет** — у номера одно, красит карточку;
3. **правила-пометки** — их может быть несколько;
4. командировка — только для роуминга;
5. правило по названию услуги;
6. умолчание из таблицы выше.

Всё это правится в интерфейсе, без правки кода: **Меню → Настройки →
Правила номеров** и **Правила оплаты**.

### Номера, за которые компания не платит

Часть номеров оплачивает сам сотрудник: компания ставит ему в списке
работников не бюджет на связь, а **сумму взноса** — 490, 90, 690, 1070.

Правило номера умеет ловить такие номера само. У каждого правила есть поле
**«Лимиты»**: перечисленные там суммы сверяются с лимитом абонента копейка в
копейку, и при совпадении правило навешивается на номер — с его цветом и со
всеми эффектами, как если бы его поставили руками. Отмечать сотню номеров
мышью не нужно, а список сумм правится там же, в настройках.

У правила «Личный тариф — платит сам» стоит признак **«Сам»**. Он означает,
что номер уходит из денег компании целиком:

* его не видно в KPI, в «платим впустую» и в расширенной аналитике;
* **подбор тарифа по нему не считается, и в потенциал экономии он не идёт** —
  компании там нечего экономить, экономия была бы чужая;
* в списке он живёт в отдельной группе — переключатель **«Платят сами за
  себя»** над карточками, со своими итогами.

Признак **«Искл.»** («не учитывать») действует так же на деньги, но номер не
попадает и в отдельную группу: он просто выпадает из всех сводок. Им помечают
безлимитные, аннулированные и уволенных.

> Раньше статусы абонента («Уволен», «Аннулирована», «VIP») были только
> подписью: цветная точка на карточке и ничего больше. Пометить номер
> аннулированным можно было, а на расчёт это не влияло никак. Статусы убраны,
> а те, что были проставлены, миграция перенесла в правила-пометки — у
> «Уволен» и «Аннулирована» сразу с галкой «не учитывать».

## Каталог тарифов и как определяется тариф абонента

Каталог собирается кодом (`domain.build_catalog`) из трёх наборов, взятых
из тарифных сеток оператора:

| Набор | Значения |
|---|---|
| Голосовые базы | Федеральный Специальный (0 ₽), пакеты 140 / 230 / 400 ₽ |
| FMC — городской номер на трубке | 16,95 ₽/мес, пакетов не добавляет |
| Интернет-пакеты | 30 ₽ (1,5 ГБ), 100 ₽ (8 ГБ), 220 ₽ (15 ГБ), 310 ₽ (30 ГБ), 400 ₽ (безлимит) |

Реальный тариф — это их **комбинация**, поэтому в каталоге 53 строки, а не
девять. Отсюда суммы, которых нет ни в одной строке сетки: 186,95 ₽ — это
16,95 + 140 + 30, а 726,95 ₽ — это 16,95 + 400 + 310.

**FMC в подборе не участвует.** Городской номер на трубке — это решение про
телефонию, а не про экономию: пакетов он не добавляет, и советовать «перейди
на такой же тариф, но с FMC» бессмысленно. Поэтому комбинации с FMC
отфильтрованы из вариантов перехода — но **из каталога не удалены**, и это
принципиально: без них номер с абонплатой 186,95 ₽ опознался бы как «Пакет
140», а весь дальнейший расчёт поехал бы от неверного пакета. Текущий тариф
абонента показывается всегда, даже если он с FMC, — иначе не с чем сравнивать.

Пакеты **складываются**: «Пакет 400 + Интернет 100» — это 4 000 мин,
1 000 SMS и 70 000 + 8 192 МБ за 500 ₽. Оператор волен показать это в счёте
и одной строкой абонплаты на 500 ₽, и двумя — «Абонентская плата по
тарифному плану» плюс «Абонентская плата за пакет "Интернет 100"». Считается
одинаково: строка про интернет-пакет тоже относится к абонплате. Иначе тариф
опознался бы без докупленного пакета, а его цена выглядела бы перерасходом
по трафику — и система советовала бы повысить тариф тому, кто уже доплатил.

**Тариф абонента определяется по абонплате из счёта**, а не по названию:
название оператор меняет и обвешивает суффиксами, а списанная сумма — факт.
Как ищем, в порядке убывания доверия — `fee` (копейка в копейку), `fee+name`,
`fee~` (в пределах 15 ₽), `name`, `nearest`. Способ уезжает на фронтенд полем
`matched_by`, чтобы догадку было видно как догадку.

**Посуточное списание приводится к полному месяцу.** Номер подключили
пятнадцатого — оператор спишет половину абонплаты, и тариф за 400 ₽ выглядел
бы в счёте как тариф за 200 ₽. Такой месяц помечается `partial_month`,
и рекомендация по нему не выдаётся: сравнивать полмесяца с моделью полного
месяца — значит показывать экономию из воздуха.

Каталог правится в интерфейсе (**Настройки → Каталог тарифов**). При
обновлении приложение подменяет каталог только если он **дословно совпадает**
со старым набором по умолчанию, то есть его никто не трогал; правки
администратора не затираются никогда.

### Роуминг

**Настройки → Роуминг** — ставки по четырём международным зонам (Европа, СНГ,
популярные, остальные) плюс Крым, из тарифной сетки оператора.

Это **справочник для сверки, а не калькулятор**: расход в отчёте берётся из
счёта как есть и по этим цифрам не пересчитывается — в счёте бывают пакеты
и акции, о которых таблица не знает. Нужна она, чтобы, увидев восемь тысяч
за поездку, иметь под рукой цену минуты и мегабайта.

## Дополнительные инструменты

### Конвертер выгрузок

```
python convert.py otche.txt
```

Делает четыре файла: три для Excel (абоненты, услуги, итоги) и один
`.bill.csv` — его можно загрузить обратно в приложение. После конвертации
выполняется круговая сверка: файл разбирается тем же парсером, что и на
сайте, и суммы сравниваются с исходником.

### Сырые строки счёта

<http://localhost:3001/raw> — содержимое таблиц `reports` и `pvalues` как
есть, без единого пересчёта: ни разделения «компания/сотрудник», ни правил
чипса. Страница собирается на сервере обычным HTML, без JavaScript, и
открывается в любом браузере — она нужна там, где смотреть базу больше
нечем. Фильтры по периоду, номеру и услуге лежат в адресной строке, ссылку
на выборку можно переслать. Кнопка «Скачать CSV» отдаёт то же самое файлом.

### Перенос старой базы SQLite

```
python import_sqlite.py --run --fresh
```

См. раздел «Установка» выше. Скрипт разовый.
